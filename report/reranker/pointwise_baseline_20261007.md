## 4. 与检索分融合的对照

将检索分与重排分各自经 `sigmoid_zscore` 校准后加权求和（权重 $w_{ret}$, $w_{rerank}$），由已落盘的候选分数与重排分数计算（%）：

| 排序方式 | R@1 | R@3 | R@5 | NDCG@5 | NDCG@10 | MRR@10 |
|---|---:|---:|---:|---:|---:|---:|
| 检索序 | 55.37 | 77.15 | 84.83 | 74.15 | 76.49 | 73.33 |
| 仅重排分（$w_{ret} = 0$） | 66.60 | 83.97 | 88.00 | 81.58 | 82.82 | 81.46 |
| $(w_{ret}, w_{rerank}) = (0.5, 1)$ | 66.03 | 83.89 | 88.14 | 81.42 | 82.60 | 81.39 |
| (1, 1) | 64.88 | 83.33 | 87.83 | 80.65 | 81.97 | 80.60 |
| (1, 0.5) | 62.74 | 81.16 | 87.13 | 78.99 | 80.56 | 78.69 |

随 $w_{ret} / w_{rerank}$ 增大（0 → 0.5 → 1 → 2），R@1、R@3、NDCG@5、NDCG@10、MRR@10 均单调下降；R@5 在 (0.5, 1) 处为 88.14，高于仅重排分的 88.00，之后下降。仅重排分比 (1, 1) 的 R@1 高 1.72 pp、NDCG@10 高 0.85 pp。
因此本基线仅按重排分排序：候选集本身由检索分筛选，再加入检索分属于重复使用同一信号；且 listwise 的最终排序同样不与检索分融合，两者口径一致。
单路分数排序时，sigmoid 与查询内 z-score 均为单调变换，不改变序，故基线排序不做校准。

## 6. 复现

```bash
cd code
python -m reranker.rerank_api --topk 10 --limit 0 --workers 8
```

响应按 `sha1(模型 + 请求体)` 缓存于 `output/common/cache/api/Qwen__Qwen3-VL-Reranker-8B/`，同配置重跑不产生新的 API 调用。`--limit` 须与 `reranker.rerank` 相同才对应同一批 query。

| 文件 | 内容 |
|---|---|
| `api_rerank_scores.jsonl` | 每条 query 的最终排序与逐候选重排分 |
| `metrics_api_rerank.jsonl` | pointwise 全指标（micro、macro、分 domain） |
| `metrics_api_rerank_baseline.jsonl` | 同批 query 的检索全指标 |
| `summary_api_rerank.json` | 配置、`scoring` 声明、Recall@5、API 统计 |
