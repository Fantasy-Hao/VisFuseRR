# 第二部分：listwise 推理重排

| 项 | 值 |
|---|---|
| 数据 | MMDocIR 文档内检索，全量 1658 query；输入为融合检索的 Top-10 候选 |
| 生成模型 | `Qwen/Qwen3.8-27B`（`/v1/chat/completions`），思考模式开启，temperature = 0 |
| 输入 | 每个候选的 OCR 文本（≤ 700 字符）+ 页面图像（最长边 896） |
| 参数 | `thinking_budget = 8192`，`max_tokens = 8192` |
| 对照 | 检索序；`Qwen/Qwen3-VL-Reranker-8B` pointwise 重排（`pointwise_baseline_20261007.md`） |
| 产物 | `output/reranker/mmdocir/Qwen3VLEmb8B/rerank/` |

三种系统使用同一批 1658 条 query、同一份 Top-10 候选与同一套指标。表中 Δ 由未取整数值计算，可能与表中两数之差相差 0.01 pp。

---

## 1. 方法

一次调用将一条 query 的全部 10 个候选交给生成模型，模型逐候选给出判断后输出完整排序，调用量为 1 次 / query（全量 1658 次）。

1. **整体推理**：10 个候选在同一次推理中比较，排序由模型直接给出，不与检索分加权；
2. **图文双路**：每个候选给出「编号 + OCR 文本」文本块与页面图像，文本块置于对应图像之前；
3. **坐标级理由**：每个候选对象的键序固定为 `id → evidence_boxes → evidence_type → relevance → reason`，证据坐标先于理由生成。

输入由三段组成：system 段（任务、输出格式、规则）；user 首块（query、候选数 n、格式复述）；候选交错块（候选 i 的文本块、候选 i 的图像，i = 1..n）及收尾复述。候选按检索序编号。

输出格式：

```text
<evidence>
[{"id": 1, "evidence_boxes": [[120, 340, 880, 610]], "evidence_type": "table",
  "relevance": 4, "reason": "..."}, ...]
</evidence>
<ranking>[1, 5, 2, 9, 3, 7, 4, 10, 6, 8]</ranking>
```

`<evidence>` 覆盖全部 n 个候选并按编号升序；`evidence_boxes` 为 0–1000 归一化整数坐标，每候选 0–3 个；`evidence_type ∈ {table, chart, figure, text, formula, other}`；`relevance ∈ {0,…,4}`；`<ranking>` 为 1..n 的完整排列。思考过程由服务端单独返回，不进入 `content`、不占 `max_tokens`，不施加格式约束。

**输出合法化**（顺序固定）：（1）取 `<ranking>`，缺失时依次退到证据段之后的最后一个整数列表、按 `relevance` 降序（同档保持检索序）、检索序；（2）丢弃越界编号；（3）按首次出现去重；（4）缺失编号按检索序补到末尾。输出恒为 1..n 的全排列，因此 Recall@10 与检索一致；K < 10 时不保证单调，故单独统计名次升降（§2.3）。调用失败的 query 整条退化为检索序并计入指标。

| 指标 | 值 |
|---|---:|

## 3. 局限

- 候选始终按检索序呈现，未做打乱顺序的多次投票，位置偏置未被分离；
- 10.3% 的请求思考量触及预算上限，更大的预算是否改变结果未验证；
- 4 条调用失败按检索序计入指标；
- 单模态消融（`--no_text` / `--no_image`）已实现，尚未运行；
- 三方对照均为点估计，未做配对显著性检验；
- 输入仅为 Top-10，Recall@5 已达到上限差距的 77.1%（§2.2）；检索 Recall@20 / Recall@50 为 95.40 / 99.10，扩大输入候选数需更长的上下文；
- 仅使用单一生成模型与单一数据集。

## 4. 复现

```bash
cd code
python -m reranker.prepare --topk 10 --limit 0 --max_side 896
python -m reranker.rerank --topk 10 --limit 0 --workers 24
python -m reranker.rerank_api --topk 10 --limit 0
```

默认参数即本报告配置。请求按 `sha1(模型 + 温度 + max_tokens + thinking 配置 + 消息体)` 缓存，同配置重跑不产生新的 API 调用；修改 `--thinking_budget` 或 `--max_tokens` 会使缓存失效。偏离默认配置的运行写入 `rerank/` 下以参数差异命名的子目录。

| 文件 | 内容 |
|---|---|
| `judgements.jsonl` | 逐 query 逐候选的坐标、类型、档位、理由、名次、`best_iou`、`is_gt_page` |
| `rerank_scores.jsonl` | 每条 query 的最终排序 |
| `metrics_baseline.jsonl` / `metrics_rerank.jsonl` | 检索与 listwise 的全指标（micro、macro、分 domain） |
| `metrics_rank_shift.json` | 名次升降与各 K 下 Recall 升降 |
| `metrics_localization.json` | IoU、containment、框面积 |
| `metrics_format.json` | 格式合规与 relevance 档位 |
| `summary_listwise.json` | 配置、指标、token 累计与峰值 |
